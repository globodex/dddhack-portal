## Verdict and gate

The reviewed Worker artifact has an adequate mitigation for the remaining advisory paths: **the affected implementations are absent from every production environment, and visitor input has no path to the build transforms**. This is an artifact-specific conclusion, not a claim that the installed dependencies were patched or that the full app has no vulnerabilities. The prior unknown-reachability release gate is cleared only for an artifact that passes `npm run test:artifact` and the compiled Worker tests described below. Every rebuild, dependency/source/manifest change and final Sites package must be checked again before publication.

The raw full audit remains visible in `evidence/sites-dependency-audit.json`: **6 high, 4 moderate, 0 low, 0 critical** package-chain findings. These represent two remaining advisories, not ten independent vulnerabilities. No audit filtering, advisory suppression, forced framework downgrade or replacement glob parser was used.

## Artifact proof

The build-only `scripts/vite/production-reachability-plugin.mjs` records bundler module membership in ignored `.sites-runtime/reachability/`, outside all public assets. It does not change emitted code. `scripts/review-production-artifact.mjs` validates the graph against current source-file, Vite config and lockfile hashes, then lexes the actual emitted JavaScript imports and hashes every final artifact file.

Evidence in `evidence/sites-artifact-reachability.json` records:

- 291 Worker/RSC modules, 120 SSR modules and 152 browser modules in the reviewed build; the sets overlap.
- Zero affected glob/parser/build/CLI modules and zero Vinext compiler/CLI entries. Vinext's actual runtime modules remain present; the npm finding against the package is inherited from its build-plugin dependency, not a separate advisory on those runtime modules. Two pure Google Fonts URL helper modules happen to live in Vinext's `build/` directory; they contain no glob parser, source transform or request-controlled compilation.
- The final module closure resolves to emitted files plus explicit platform modules (`cloudflare:workers` and named Node builtins). No npm package remains external. No fixture SQLite runtime, fake inventory seed, development connector service, Git metadata, node_modules installation or environment file enters the artifact.
- One nonliteral React development-renderer import remains in SSR code. An AST check proves it is in the consequent of an unreassigned, zero-argument function compiled to literal `false`. Its suffix is a fixed React development filename, not visitor input. This retained dead branch is reported explicitly. Any other nonliteral import fails the gate.
- Current API code accepts an explicit command allowlist, bounded JSON/CSV and parameterized D1 values. Profile/team/project fields are data, not code or glob patterns. The evaluator makes no external fetch, executes no participant repository code and does not load modules from submitted URLs. React escapes user text. Framework config matchers compile fixed operator-authored configuration, not request-supplied match patterns.

The official Sites `package-site.mjs` / `prepare-site-build.cjs` workflow copies `dist/` plus reviewed Drizzle metadata, not the dependency installation. The local package review records archive entries and compares each file's digest with the checked artifact. The initial local review archive had no Site ID and was not a saved or deployed version. The approved publication subsequently rebuilt and rechecked the artifact through the official source workflow after persisting the real project ID; see `PUBLICATION.md`.

## Non-destructive tests

- `npm run typecheck`, all 19 service/D1 tests, the official Sites build and `npm run test:production` pass after the maintained toolchain fix.
- The compiled Worker round-trips a 256-level nested-brace profile string as literal data, returns 404 for a brace-bearing team lookup and remains responsive. Source/dev endpoints expose neither Vite client source nor an event stream. Standalone forged owner headers/local fixture cookies fail closed; synthetic Dispatch tests retain participant/admin/export/judge restrictions.
- `scripts/review-advisory-inputs.mjs` runs one caught local braces check in a separate process, capped at 64 MiB heap and five seconds. A 4,097-character, 2,048-level pattern yields `RangeError`, confirming that the installed build dependency is still vulnerable. The production mitigation is not misrepresented as a dependency patch.
- `scripts/test-artifact-gate.mjs` proves that the gate rejects a newly added external npm import, a new nonliteral import, an affected module in the build graph unrecorded JavaScript chunks and stale graph metadata. Only generated local files are temporarily modified; `finally` restores exact original bytes and the restored artifact must pass. Those injected statements are parsed, never executed or deployed.

The probes are bounded supporting evidence; they do not prove all possible runtime behavior safe. Continue upstream patch tracking. New compilation/network evaluator features, new dependencies, untrusted build inputs or any closure change require a fresh review.
