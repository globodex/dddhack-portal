# Direct admin credit values

Isolated branch `feat/admin-credit-values`, based on root `41bea03a79386a8208ac95afe5ea622a0581aa49`. Integrate `1e89fa8` (projection/UI), `af9473d` (SSR-safe stylesheet import), and `ff83ae6` (focused tests and browser QA). Final browser evidence ran against committed `ff83ae6`.

`GET /admin/credit-stock/:typeId` and its `/assigned` or `/available` filters still perform fresh `s.staff()` authorization before stock access. Page size remains 25 with the existing search, totals and pagination. The selected page returns `value: string | null`, `codeAvailability: "ready" | "unavailable"`, and `codeError: string | null`. Values come only from that page's database `voucher_value` or legacy decryption. Ciphertext, encryption keys, provider configuration and masked-code placeholders are not returned.

The admin table displays all readable values on the current page immediately, with Copy. It issues no Reveal/Hide command or exposure polling and never fetches all pages. Failed decryption displays Code unavailable, a fixed actionable owner-verification message, and disabled Copy. Clipboard denial leaves the visible code selectable and reports the failure honestly. Loads are aborted and old page data cleared when the query, filter, page or component changes.

Personal credit projections and own-code reveal behavior were not changed. Compatibility `admin-reveal-credit` remains available to older callers. Displaying stock does not allocate a code, mark it exposed, change a mapping, or append audit entries. Permanent hash retirement remains independent of the exposed flag.
