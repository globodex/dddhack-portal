# Admin presentation helper boundary

`lib/admin-presentation.ts` provides an optional delta protocol only for `/admin/participants` and `/admin/teams`. It must run after fresh service authorization/projection. All responses still require private/no-store headers. Root owns HTTP and Portal integration, known-version requests, full-response retry and lifecycle calls.

Only `name`, `avatarColor`, `avatarExpression`, `teamName`, `teamPalette` strings/null are eligible. IDs always remain in fresh rows. Rows without a valid signed-in ID stay wholly fresh; email is never a cache key. Snakecase `team_name`, team palette, nested members, private ideas, email, phone, credits, status, locks, readiness and votes remain fresh. No browser persistence, process-global state, database/auth cache or shared-user cache exists.

Scope hashes the freshly authorized actor ID/role/owner, canonical permitted route and bounded canonical options. Version hashes actual safe field values and the exact ID set. A name/avatar/team presentation change invalidates the version; locks imply no immutability. An unchanged packet omits safe fields only. The per-Portal memory cache holds one snapshot, requires exact scope/version/IDs and rejects contradictory or incomplete packets with `AdminPresentationCacheMiss`, signaling full retry. `clear()` is protected against in-flight hash completion and must be called on pagehide/logout/account changes. Unsupported paths/roles or malformed row identity sets are returned full without cache metadata.

TypeScript and7targeted tests passed. They cover fresh volatile/private changes, byte reduction on an unchanged label snapshot, avatar/name/membership presentation invalidation, actor/role/owner/route/options scoping, null-ID rows, removed/reordered IDs, missing snapshots, contradictory/tampered packets and async clear races. Real disposable SQLite projections verify approval/status/readiness freshness, changed avatars/names, an authorized unlocked admin idea override remaining fresh, and role revocation denial.

The real locked-idea override test discovered an existing shared-service defect: `admin-idea-override` uses an UPSERT that hits unguarded `locked_ideas_insert` before the guarded update. It throws TEAM_LOCKED despite the authorized update guard. Root was notified with the exact action/cause. No trigger was bypassed or dropped; the cache test uses the supported unlocked path and separately verifies locked-name direct updates remain denied. Root owns fixing/validating any locked override flow.

The optimization can reduce repeated response bytes and reuse safe presentation values. It does not reduce fresh authorization or database projection work. Browser integration and actual before/after Admin response-byte measurements remain with root.
